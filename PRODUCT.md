# UmiBridge

Local Windows gateway exposing authorized file, shell and desktop tools to ChatGPT through MCP, with a private dashboard.

## Corp

User-controlled chat orchestration within the existing UmiBridge dashboard. Users can register chats and define an ordered sequence, enter an idea and explicitly start a predefined project workflow, or create an Arena that provisions one ChatGPT Project with eight department chats and compares 20, 50 or 100 product variants. Arena defaults to groups followed by knockout, with knockout-only available. Candidates reuse those Project chats sequentially. Creation checkpoints and uncertain outcomes persist; unknown creation or send outcomes stop for reconciliation. The Pixel Agents office reflects real queue state. Provider quota notices pause tasks until their stored reset deadline.

Arena uses full product delivery. Setup creates the Project before its eight child chats, then leaves the Arena paused for review and explicit start. The UI separates Office, Idea, Arena and Queue; each Arena has Live, Groups, Bracket, History and Products tabs. Arena history stays scoped to the selected Project; candidate/judge tasks stay out of the ordinary queue. Persisted match reports, criteria scores, checks, standings, bracket rounds, lifecycle history and winner artifacts expose recorded state. Animation reflects processing state, respects reduced motion and never invents scores or results.

Groups contain five products and play a single round robin. The top two advance to knockout. Ranking uses three points per win, then score difference, total score and original seed order. Each comparison uses five criteria: requirements/function 35, UX 15, tests/evidence 20, security 15 and local delivery/docs 15. Structured criteria totals and nonempty scoped evidence files are required; those gates do not independently certify the content of a report. Group-plus-knockout has 47/119/239 judged matches and 267/669/1339 baseline tasks for 20/50/100 products. Knockout-only has 19/49/99 matches and 239/599/1199 tasks. Baseline tasks equal eleven stages per product plus judged matches, before bounded repairs. Counts do not estimate provider prices or quota. The format is fixed at creation; the API accepts `format: "group_knockout"` or `format: "knockout"`.

Target devices: desktop and laptop at 1600x1000 and 1366x768. No narrow-screen feature development or mobile QA. Preserve existing OAuth, tools, privilege controls and dashboard visual identity. Queues, setup state and chat content remain in excluded private state; new Idea and Arena projects use a selected local parent folder, with Documents/UmiBridge Projects as the default. A local dashboard dialog browses directory metadata; typed paths remain supported. Each request persists a canonical parent and exclusive project subfolder. Existing project folders stay fixed. The idea workflow has fixed roles and stages, at most two repair rounds, and explicit report gates; model text cannot choose recipients or append arbitrary tasks. No new AI service, account switching, quota bypass, background monitoring or automatic public deployment. The separate Workflows ledger retains its manual contract. Real-account evidence covers Project/eight-chat bootstrap and a paused workflow; a complete real-LLM Arena tournament remains unverified.
